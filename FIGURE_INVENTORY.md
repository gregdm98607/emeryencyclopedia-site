## Key findings

1. **The "six legacy matplotlib figures" undercounts the real problem by a lot.** Every `chNN_figure_*.svg` currently in `public/images/chapters/` was inspected for its embedded metadata. All 42 of them — spanning roughly 30 chapters (ch06 through ch40) — carry `<dc:title>Matplotlib v3.10.9` provenance tags. None match the newly locked EEC branded system (Archivo Black type, the nine reconciled site-token colors, single hand-authored root `<svg>`). The plan's Phase 1 pilot list (ch02, ch03, ch04×2, ch05, +1 unconfirmed) is really the tip of a much larger rebuild: **14 currently-listed proposed figures already have a matching legacy matplotlib asset** built against them (tagged `legacy-rebuild` below), and that's only counting figures still named in the chapters' own "Proposed Figures" text — a further ~14 matplotlib assets exist for chapters whose proposal line was already deleted once the (legacy-style) figure got built, so the true legacy-rebuild count across the whole site is closer to the high 20s.
2. **Most chapters never had a standalone "Proposed Figures" list.** Only Ch02 splits Maps / Figures / Photographs into separate sections (its native `F1`–`F5`, `M1`–`M5`, `P1`–`P10` tags were carried straight into this table). Every other chapter that has one at all merges them into a single "Proposed Maps and Figures" (or "…/Photographs") section, phrased a different way in nearly every chapter (`Maps & Figures`, `Maps and Figures`, `Maps/Figures`, `Maps / Figures / Photographs`, etc.). This inventory parsed all of those variants, then split each item back out by what its own text says it is (an explicit "Map —", "Photo —", "Portrait", "Reproduction", "Facsimile", etc. beats the section header). That reclassification is exactly the status vocabulary's `better-as-a-map` / `better-as-a-photo` values are for.
3. **Six chapters have no proposed-visuals section at all:** Ch01, Ch05, Ch19, Ch41, Ch42, Ch43. Ch41–43 are backmatter (bibliography, glossary, index) and genuinely don't need figures. Ch01 and Ch05 already ship 3 and 6 sourced photographs respectively with no figure proposal outstanding — plausibly fine as-is. **Ch19 ("Water for the Desert") is the one worth flagging**: it has zero `<FigureImage>` embeds and zero proposed-visuals text, yet `ch19_figure_water-development-timeline.svg` already exists as a built (legacy matplotlib) asset on disk — built, but neither wired into the chapter nor tracked by any remaining proposal line. This is the MDX-wiring gap already on record; Ch19 is a concrete instance of it.
4. **Ch02's own status notes from `FIGURE_ROLLOUT_PLAN.md` reconcile cleanly with this inventory.** F2 (stratigraphic column) matches the existing `ch02_opensource_geological_timeline.png` and is tagged `legacy-rebuild`. F4 (uranium roll-front) has a drafted-but-unapproved trio sitting in `figure-curation/proposed/` (`ch02-F4-uranium-roll-front.html/png`) — flagged `todo` with a note, since the plan's Phase 0 checklist doesn't count a Greg-unapproved draft as shipped. ## Methodology & scope (read before trusting a specific row)

- **Parsing.** Every `## ...Propos[ed]...` heading whose text mentions Map/Figure/Photo/Chart/Diagram/Illustration/Visual/Imagery was captured, then split into list items (bullet or numbered, bold-label or plain). Sections that only ever say "Proposed Maps" or "Proposed Photographs" (i.e., no "Figure"/"Chart"/"Diagram" word in the header at all) were excluded entirely — those are Ch02's genuinely separate Maps/Photographs lists, not part of its Figures list, and are out of scope for this table. "Proposed Tables" sections were excluded the same way; any inline item explicitly starting "Table —" was dropped too.
- **Classification (map / photo / figure).** Priority order: (1) an explicit keyword in the item's own text — map/maps, or photo/photograph/portrait/reproduction/facsimile/mascot/skeleton/dust-jacket/front-page/exterior/snapshot — wins regardless of any author tag or section header, because catching a mis-filed item is the point of this pass; (2) the chapter's own `F#`/`M#`/`P#` planning-ID convention (Ch02 only); (3) the section header, when it names exactly one kind; (4) default to figure. **14 items were hand-reclassified** beyond what the keyword rules caught (facsimiles, book covers, a memorial-wall photo, a GIS/lidar demo, etc.) — flagged `manual reclassification` in the Notes column. This is a best-effort text-based read, not a build-status check on every map/photo item — treat the 82 map and 98 photo rows as "needs a human glance," not gospel.
- **Chart-form suggestion.** Extracted from explicit language in the item's own text ("line chart," "bar chart," "cross-section," "timeline," "infographic," etc.) where present; inferred from FIGURE_SYSTEM.md's own rule (a *measured* quantity over time → line/area chart; something that *existed* for a span → span bars) where not; 10 items needed a fully manual read. Treat every suggestion as a starting point for the per-chapter session recipe's step 2, not a final call.
- **`legacy-rebuild` vs `todo`.** Every `chNN_figure_*.svg` in `public/images/chapters/` was checked for matplotlib provenance (all 42 are matplotlib — see Finding 1). A proposed figure item is tagged `legacy-rebuild` when its own text shares at least 2 distinctive words with an existing matplotlib asset's filename slug for that chapter (or all words, for a 1–2-word slug); Ch02–05 additionally checked against the plan's own named Phase-1 targets (`stratigraphic-column`, `dissolved-solids`, `precip-gradient`, `valley-comparison`, `elevation-profile`). No chapter anywhere has a figure built under the *new* locked system yet, so `done` never applies to a figure-kind row in this table — the earliest any row can reach `done` is after Phase 1/2 actually ship something.
- **Planning IDs.** Carried over verbatim where the chapter uses its own tag (`ch02-F3`, `ch22-Fig22.1`); auto-numbered per kind in reading order where the chapter uses plain prose (`ch27-F4(auto)`) — the `(auto)` suffix means the number is this inventory's own ordering, not a number that appears in the chapter text.
